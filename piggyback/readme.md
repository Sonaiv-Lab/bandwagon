## npm script 

types: 
- start : command to start service
- dev: command to dev
  - may able to hot reload 
- check: code linting , type checking process
- format: do something in code base which logic irrelated
- secret:cloud => get secret by gcloud, it need install manually in local

### run time and bundle factors

there are some different factor about app execution
- bundled or not
- environment
  - cloud on local run?
    - when deploy as cloud service, always bundled (as cloud function) or dockerize (as node app)
    - cloud function also can run as local simulation
  - runtime
    - node app
    - function
- is dockerize?
  - the goal of containerize (dockerize) is to simulate production app. so always bundled

compose these factors, here is the available runtime combination


node runtime
- local:node:unbundled:not-dockerize
- ~~cloud:node:unbundled:not-dockerize~~ => node runtime always dockerize and bundled on cloud 
- local:node:bundled:not-dockerize => useful when check bundle process
- ~~cloud:node:bundled:not-dockerize~~ => node runtime always dockerize and bundled on cloud 

- ~~local:node:unbundled:dockerize~~ => dockerize always bundled
- ~~cloud:node:unbundled:dockerize~~ => dockerize always bundled
- local:node:bundled:dockerize => useful when simulate cloud in local
- cloud:node:bundled:dockerize => for production


cloud runtime (no need dockerization)
- local:function:unbundled => nice for local dev or simulation
- local:function:bundled => nice for checking bundle process

- ~~cloud:function:unbundled~~ => alway bundled on cloud
- cloud:function:bundled => for production

after clarify the different scenario, we can get back into env topic


### why only local dev need dotenvx that use .env file?
the are some concept about environment variable

- when use docker, when should docker built-in mechanism:
  -  utilize [commands](https://docs.docker.com/reference/cli/docker/container/run/#env) `docker run --env` or `docker  run --env-file`
  - or [docker compose](https://docs.docker.com/compose/how-tos/environment-variables/set-environment-variables/#use-the-env_file-attribute)
- when on cloud platform, we should utilize the secret manager.
- cloud function local simulation has their own way to inject `.env`

After the clarification, the only needed of dotenvx is local run and not dockerized scenario which are mentioned above:  

- local:node:unbundled:not-dockerize
- local:node:bundled:not-dockerize
